# 趋势双向阶梯策略

## 1. 策略定位

这个策略建立在现有庄家雷达的扫描能力之上，但交易目标不同：

- 现有雷达偏向发现收筹、OI 异动、负费率燃料和潜在拉盘。
- 新策略偏向发现已经脱离横盘、可能进入大波动区间的代币。
- 策略不预测多空方向，只判断标的是否值得进入双向挂单测试。

核心原则：

> 不预测方向。先用一组多空同时开的对冲试探仓进入市场，等行情真正走出方向后，只沿盈利方向继续加仓，直到趋势摸顶/摸底后整体退出。

## 2. 状态流

策略状态分为：

```text
SCANNING          全市场扫描
CANDIDATE         趋势候选
HEDGED_PROBE      首组多空对冲试探仓已开
LONG_ACTIVE       确认向上，只加多单；空单首仓作为对冲腿保留
SHORT_ACTIVE      确认向下，只加空单；多单首仓作为对冲腿保留
FULL_POSITION     趋势方向 10 单全部成交，进入高位/低位风险监控
PROFIT_TAKING     动态分批止盈中
STOPPED           止损退出
CANCELLED         条件失效或超时取消
COMPLETED         策略完成
```

当前代码先实现扫描、评分、生成计划、落库、推送和回测。真实下单前需要确认执行器支持 hedge mode、同币多空双持、策略组联动平仓。

## 3. 扫描过滤

基础过滤：

- 只扫描 USDT 永续合约。
- 排除稳定币、指数和明显不可交易合约。
- 24h 成交额必须达标，默认不低于 `10,000,000 USDT`。
- 点差和交易所精度规则需要在执行端二次校验。
- K 线数据不足时不进入候选。

横盘过滤：

- 使用 5m 和 15m K 线判断。
- 最近 5m 区间振幅过小，不交易。
- ADX 过低，不交易。
- ATR 没有扩张，不交易。
- 成交量没有扩张，不交易。
- EMA 仍然缠绕，不交易。

默认入选条件：

```text
trend_score >= 70
ADX >= 25
volume_ratio >= 1.35
atr_expansion >= 1.10
range_pct >= 4%
```

## 4. 趋势评分

`trend_score` 满分 100：

| 模块 | 满分 | 说明 |
| --- | ---: | --- |
| 波动扩张 | 25 | ATR 扩张越明显越高 |
| 成交量扩张 | 20 | 近期均量 / 前期均量 |
| ADX 趋势强度 | 25 | 只判断有无趋势，不判断方向 |
| EMA 分离 | 15 | EMA9、EMA21、EMA55 不再缠绕 |
| 区间突破准备 | 15 | 当前价格靠近区间上沿或下沿 |

入选以后并不直接开仓，只生成双向阶梯挂单计划。

## 5. 首单对冲与趋势加仓结构

先定义最近区间：

```text
upper = 最近 N 根 5m K 线最高价
lower = 最近 N 根 5m K 线最低价
atr = 15m ATR
```

第一组订单不是二选一，而是同时开：

```text
LONG_1  = 当前价附近或突破确认价
SHORT_1 = 当前价附近或突破确认价
```

这组订单的作用是“进市场测试”，方向风险接近中性。之后根据价格相对区间的位置确认方向：

```text
价格站上 upper + buffer，并持续推进 => LONG_ACTIVE
价格跌破 lower - buffer，并持续推进 => SHORT_ACTIVE
```

确认多头后：

```text
LONG_1 + LONG_2 ... LONG_10
SHORT_1 保留为对冲腿，不继续加仓
```

确认空头后：

```text
SHORT_1 + SHORT_2 ... SHORT_10
LONG_1 保留为对冲腿，不继续加仓
```

如果行情没有确认方向，首组对冲仓可以小亏手续费/滑点后退出，不进入加仓阶段。

## 6. 仓位权重

趋势方向最多 10 单，价格越顺着趋势走，单笔金额越大。也就是：

- 多头趋势：价格越涨，加的多单越大。
- 空头趋势：价格越跌，加的空单越大。
- 初始对冲首单最小，后续只给盈利方向放大仓位。

如果 10 张单全部下完后，趋势方向最大名义仓位是 `1000U`，使用“成本越低仓位越大、越往后仓位越小”的权重：

```text
22%, 18%, 15%, 12%, 10%, 8%, 6%, 4%, 3%, 2%
```

对应 `1000U`：

```text
第1单：220U   首组对冲试探，LONG_1 和 SHORT_1 各 220U
第2单：180U   方向确认后，只加趋势方向
第3单：150U
第4单：120U
第5单：100U
第6单： 80U
第7单： 60U
第8单： 40U
第9单： 30U
第10单：20U
合计：1000U
```

原因：

- 首组位置成本最有优势，所以仓位最大，但用多空同时开来对冲方向不确定性。
- 趋势越往后，越接近顶部/底部风险区，所以加仓金额逐步变小。
- 盈利方向不断加仓，但不是越追越重，而是越追越轻。
- 10 单全满后，说明趋势已经走得很远，策略从进攻切换到摸顶/摸底和锁利。

单方向总名义仓位从风险倒推：

```text
单币风险预算 = 账户允许亏损
止损距离 = 10%
单方向最大名义仓位 = 单币风险预算 / 10%
```

例如单币风险预算 `100 USDT`，则单方向最大名义仓位约 `1,000 USDT`。

## 7. 策略组联动约束

这是执行端必须保证的硬规则：

- 首组 `LONG_1 + SHORT_1` 必须绑定同一个 `strategy_group`。
- 确认多头后，只允许加多单；`SHORT_1` 保留为对冲腿。
- 确认空头后，只允许加空单；`LONG_1` 保留为对冲腿。
- 主动趋势腿退出时，对冲腿必须同时平掉。
- 任何情况下不能留下单独裸露的对冲腿。
- 如果执行端意外在两个方向都有额外成交，必须把全部同币同策略仓位绑定成一个 strategy_group，一起退出。

这个规则的目标不是让首单赚钱，而是让首单提供方向测试和波动缓冲，真正利润来自确认方向后的趋势加仓。

## 8. 止损规则

止损不再按单边裸仓简单计算，而是按策略组净值和趋势失败来处理。

首组对冲阶段：

```text
如果未确认方向，并且持仓超过观察窗口，退出 LONG_1 + SHORT_1
如果对冲组净亏损超过手续费/滑点容忍范围，退出
```

趋势加仓阶段：

```text
如果趋势腿已经加仓，但价格重新回到区间内部，退出趋势腿 + 对冲腿
如果策略组净回撤超过预算，退出趋势腿 + 对冲腿
如果趋势腿浮盈回撤触发保护线，退出趋势腿 + 对冲腿
```

对冲腿独立止损：

```text
确认多头后，SHORT_1 亏损达到约 10%，平掉 SHORT_1
确认空头后，LONG_1 亏损达到约 10%，平掉 LONG_1
```

对冲腿止损后的状态：

- 对冲腿亏损固定，不再继续拖累趋势利润。
- 趋势腿继续持有和加仓。
- 后续止盈/止损按“已实现对冲亏损 + 趋势腿浮盈”计算策略组净利润。
- 趋势腿最终退出时，如果对冲腿已平，则只平趋势腿；如果对冲腿未平，则一起平。

硬止损仍然存在，但不以单个方向的 10% 为唯一标准，而是看：

- 策略组净亏损
- 趋势腿均价反向距离
- 是否重新跌回/涨回震荡区间
- 对冲腿亏损是否已经明显拖累净利润

## 9. 动态止盈

止盈继承现有雷达项目的动态止盈思路：不猜顶部/底部，但盯 K 线结构和利润回撤。

成交阶段分层：

```text
首组对冲：只验证方向，不追求利润。
2-4 单成交：趋势确认阶段，允许利润跑，不急于止盈。
5-7 单成交：趋势加速阶段，开始上移策略组净利润保护线。
8-10 单成交：趋势延伸阶段，进入敏感锁利。
10 单全满：默认进入 FULL_POSITION，重点盯 K 线摸顶/摸底。
```

满仓后的分批止盈：

- 轻微衰减：止盈 20%-30%。
- 明确滞涨/滞跌或跌破/站回短周期均线：再止盈 30%。
- 反向 K 线确认或利润大幅回撤：继续止盈 30%。
- 剩余仓位交给移动保护线跟随趋势。

浮盈加仓后的锁利规则：

- 趋势腿 5 单及以上成交，且策略组净浮盈明显扩大，保护线开始锁住峰值净利润的 30%-40%。
- 趋势腿 8 单及以上成交，保护线锁住峰值净利润的 45%-55%。
- 趋势腿 10 单全满，保护线锁住峰值净利润的 60% 左右，并重点看 K 线摸顶/摸底。
- 如果趋势腿没满但单边浮盈已经非常大，也提前启动净利润保护线。

这样处理的逻辑是：越往后成交，说明价格越向趋势末端延伸，仓位也越接近满仓，此时不能只看硬止损，必须让利润保护线跟着峰值浮盈移动。

多单重点观察：

- 连续 2-3 根 K 线无法创新高。
- 放量长上影。
- 大阳后小实体横盘。
- 跌破 EMA9/EMA21。
- 成交量放大但价格推进变弱。
- 最高浮盈明显回撤。

空单反向观察：

- 连续 2-3 根 K 线无法创新低。
- 放量长下影。
- 大阴后小实体横盘。
- 站回 EMA9/EMA21。
- 成交量放大但下跌推进变弱。
- 最高浮盈明显回撤。

## 10. 订单失效

双向计划不应该一直有效。

默认失效规则：

- 计划生成后 2 小时没有任何成交，重新评估。
- `trend_score` 跌破 60，取消计划。
- ADX 跌破 20，取消计划。
- 成交量扩张消失，取消计划。
- 价格重新回到窄幅横盘结构，取消计划。
- 同一代币止损后冷却 4 小时。

## 12. 批量回测

当前回测脚本：

```bash
python3 scripts/backtest_trend_ladder.py \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT \
  --start 2026-01-01 \
  --end 2026-05-01
```

也可以按当前 24h 成交额批量选币：

```bash
python3 scripts/backtest_trend_ladder.py \
  --radar-watchlist \
  --watchlist-limit 50 \
  --start 2026-01-01 \
  --end 2026-05-01
```

如果只想回测庄家雷达池里已经开始放量/放量启动的币：

```bash
python3 scripts/backtest_trend_ladder.py \
  --radar-watchlist \
  --active-radar-only \
  --watchlist-limit 50 \
  --start 2026-01-01 \
  --end 2026-05-01
```

也可以按当前 24h 成交额批量选币作为对照组：

```bash
python3 scripts/backtest_trend_ladder.py \
  --top-volume 20 \
  --start 2026-01-01 \
  --end 2026-05-01
```

回测逻辑：

- 按历史 K 线每小时重放一次扫描。
- 入选后先同时开 `LONG_1 + SHORT_1` 对冲试探仓。
- 后续 K 线确认方向后，只加趋势方向第 2-10 单。
- 反方向首单保留为对冲腿，不继续加仓。
- 退出时趋势腿和对冲腿按 `strategy_group` 一起平掉。
- 10 单全满后，如果出现 K 线衰减，触发动态止盈。
- 如果策略组净利润从峰值明显回撤，触发利润回撤退出。
- 若成交后 2 小时内只成交少量订单且峰值浮盈不足，提前按弱趋势退出。
- 若成交后 6 小时仍未形成足够浮盈，按弱趋势超时退出，减少无效占用。

输出：

- `backtests/trend_ladder_backtest.json`
- `backtests/trend_ladder_backtest.csv`

第一版回测还没有纳入手续费、滑点、资金费率、盘口深度和真实撮合队列，因此结果用于策略参数比较和方向验证，不直接等同实盘收益。
